## 1. Введение

Задача заключается в реализации повышения контраста изображения с помощью последовательной и параллельной версий алгоритма. Так же предстоит создать функциональные тесты, для проверки корректности и тесты на производительность, для сравнения реализаций. 

Входные данные в моем случае представляют собой одномерное представление изображения, вектор яркостей пикселей в диапазоне 0, 255. За счет умножения яркости каждого пикселя на фиксированный коэфицент, с последующим ограничением результата этим диапазоном, происходит повышение контраста.

## 2. Постановка задачи

Дан какой либо вектор x с длинной n, где x(i) - яркость пикселя от 0 до 255. Нужно получить вектор y, который описывает изображение с повышенным контрастом.

Я исполюзую в данной задаче простейшую линейную модель повышения констраста

y_i = clamp(⌊x_i · k⌋, 0, 255),   i = 0, …, N-1

где:
k = 1.3 это коэффициент усиления контраста, а clamp ограничивает значение снизу 0 и сверху 255.

Входные данные:
-одномерный массив (вектор) яркостей пикселей `InType`
- в функциональных тестах в качестве входа используется изображение `pic.jpg`, загружаемое через `stb_image` и разворачиваемое в одномерный массив.

Выходные данные:
- вектор `OutType` (также `std::vector<uint8_t>`), который содержит новое изображение с повышенным контрастом.

Цель:
Реализовать повышение контраста в последовательном режиме и в режиме MPI и сравнить время работы данных реализаций при одних и тех же входных данных.

## 3. Базовый алгоритм (последовательный)

Последовательный алгоритм реализован в классе `DoroginVContrastsRaisingSEQ`

Алгоритм:
Первым делом валидация - вектор не должен быть пустым. На этапе препроцессинга выходной вектор инициализируется нулями той же длины, что и входной. В методе RunImpl все элементы входного массива обрабатываются последовательно.

Основной цикл выглядит как линейный проход по массиву:

```cpp
const auto& src = GetInput();
auto& dst = GetOutput();

for (size_t i = 0; i < src.size(); ++i) {
  const int adjusted =
      static_cast<int>(static_cast<float>(src[i]) * kContrastFactor);
  dst[i] = static_cast<uint8_t>(std::clamp(adjusted, 0, 255));
}
```

Где kContrastFactor = 1.3F. Следовательно, каждая яркость умножается на коэффициент и обрезается при выходе за пределы диапазона от 0, до 255. Постобработка проверяет, что размер выходного вектора совпадает с размером входного.

## 4. Схема распараллеливания (MPI)

Параллельная версия реализована в классе `DoroginVContrastsRaisingMPI`

Основные идеи распараллеливания:
Входящий вектор яркости распределяется по блокам между процессами между процессами. Независимое повышение контраста над своей частью данных процессором.Результаты собираются обратно в корневой процесс rank 0

Распределение данных:

1. Корневой процесс (`rank 0`) знает полный входной массив `GetInput()`.
2. Число элементов делится между процессами почти поровну:
   - вектор `counts` хранит количество элементов для каждого процесса,
   - вектор `offsets` — смещения (дисплейсменты) для каждого процесса;
     они вычисляются с помощью `std::partial_sum`.
3. Для рассылки используется `MPI_Scatterv`:

```cpp
MPI_Scatterv(sendbuf, counts.data(), offsets.data(), MPI_UNSIGNED_CHAR,
             local_input.data(), counts[rank], MPI_UNSIGNED_CHAR,
             0, MPI_COMM_WORLD);
```

Где `local_input` — локальный кусок входного массива на каждом процессе.

Локальная обработка на процессе:

```cpp
for (size_t i = 0; i < local_input.size(); ++i) {
  const int adjusted =
      static_cast<int>(static_cast<float>(local_input[i]) * kContrastFactor);
  local_output[i] = static_cast<uint8_t>(std::clamp(adjusted, 0, 255));
}
```

Сборка результата:

- Корневой процесс выделяет память под полный выходной массив `GetOutput()`,
-затем вызывается `MPI_Gatherv`:

```cpp
MPI_Gatherv(local_output.data(), counts[rank], MPI_UNSIGNED_CHAR,
            recvbuf, counts.data(), offsets.data(),
            MPI_UNSIGNED_CHAR, 0, MPI_COMM_WORLD);
```

Следовательно, каждый такой процесс обрабатывает свою часть данных, а результат собирается на rank 0. Постобработка проверяет равенство размеров входного и выходного векторов.

## 5. Детали реализации

### Структура кода

`tasks/dorogin_v_contrasts_raising/`

- `common/include/common.hpp` — общие типы данных (`InType`, `OutType`, `TestType`, идентификаторы настроек и пр.).
- `mpi/include/ops_mpi.hpp` — объявление класса `DoroginVContrastsRaisingMPI`.
- `mpi/src/ops_mpi.cpp` — реализация параллельной версии (распределение данных, вызовы MPI, локальная обработка).
- `seq/include/ops_seq.hpp` — объявление класса `DoroginVContrastsRaisingSEQ`.
- `seq/src/ops_seq.cpp` — реализация последовательной версии.
- `tests/functional/main.cpp` — функциональные тесты (сравнение с эталоном для реального изображения `pic.jpg`).
- `tests/performance/main.cpp` — тесты на производительность (генерация случайного вектора яркостей и сравнение скорости seq/MPI).

### Функциональные тесты

Функциональные тесты построены на базе `ppc::util::BaseRunFuncTests`, а так же используют реальное изображение.

1. На процессе rank 0 загружается изображение `pic.jpg` с помощью `stbi_load`:

```cpp
const std::string img_path =
    ppc::util::GetAbsoluteTaskPath(PPC_ID_dorogin_v_contrasts_raising, "pic.jpg");

uint8_t* data = stbi_load(img_path.c_str(), &w, &h, &c, STBI_rgb);
```

2. Изображение разворачивается в одномерный массив `input_` длины `w * h * STBI_rgb`.
3. Вектор `input_` широковещательно рассылается каждому процессу через `MPI_Bcast`, чтобы каждая реализация задачи seq и mpi имела один и тот же вход.
4. Эталонный результат `expected_` считается локально по той же формуле усиления контраста:

```cpp
std::transform(input_.begin(), input_.end(), expected_.begin(),
               [](uint8_t v) {
                 return static_cast<uint8_t>(
                     std::clamp(static_cast<int>(v * kFactor), 0, 255));
               });
```

5. Метод `CheckTestOutputData` сравнивает выходной вектор с эталоном только на rank 0. Для остальных процессов тест возвращает `true`, так как их вывод не используется напрямую:

```cpp
if (rank != 0) {
  return true;
}
return out.size() == expected_.size() &&
       std::equal(out.begin(), out.end(), expected_.begin());
```

Параметризация тестов `kParams` задаёт разные режимы запуска через настройки `PPC_SETTINGS_dorogin_v_contrasts_raising`.

### Тесты производительности

Тесты производительности реализованы на базе `ppc::util::BaseRunPerfTests`. В них:

вектор input генерируется и имеет фиксированный размер, к примеру 1000000 элементов, со значениями яркостей в диапозоне от 0 до 255
Эталон expected вычисляется по такой же формуле повышения контраста с коэффициентом kFactor равным 1.3F. Для каждого режима seq,mpi выполняется несколько прогонов, а утилиты курса измеряют и усредняют время выполнения.

## 7. Результаты и обсуждение

### 7.1 Корректность

Функциональные тесты сравнивают результат работы задач `DoroginVContrastsRaisingSEQ` и `DoroginVContrastsRaisingMPI` с эталонным результатом, рассчитанным на основе загруженного изображения `pic.jpg`.

Критерий корректности:

Входной и выходной вектора должны быть одинаковы по размеру
Значения элементов выходного вектора совпадают с эталонными значениями

Все функциональные тесты `ContrastFunctionalTests/DoroginVRunFuncTests.*` проходят успешно для последовательной и параллельной реализации при различных параметрах теста.

### 7.2 Производительность

Тесты на производительность показывают ожидаемое поведение:

Последовательная версия (seq) служит базовым уровнем времени выполнения,
MPI-версия при увеличении числа процессов показывает ускорение за счёт распараллеливания обработки элементов вектора.

Результаты измерений производительности:

| Режим | Процессы | Время, мс | Ускорение |
| ----- | -------- | --------- | --------- |
| seq   | 1        | 15.49     | 1.00      |
| mpi   | 1        | 18.61     | 0.83      |
| mpi   | 2        | 11.26     | 1.38      |
| mpi   | 4        | 10.28     | 1.51      |

Во время выполнения данной работы были реализованы:
Версии алгоритмов линейного повышения контраста изображения, последовательный и параллельный
