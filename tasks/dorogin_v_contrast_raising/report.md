1. Введение

Задача состоит в реализации последовательной и параллельной версий алгоритма повышения контраста изображения, а также создании функциональных тестов для проверки корректности работы и тестов на производительность для сравнения последовательной и параллельной реализаций.

Повышение контраста изображения позволяет улучшить визуальное восприятие, выделить детали и подготовить данные для дальнейшей обработки.

2. Постановка задачи

Вход: одномерный массив пикселей InType размером N.

Выход: массив пикселей OutType того же размера, с увеличенным контрастом.

Описание алгоритма: каждый элемент массива масштабируется коэффициентом 1.3 и ограничивается диапазоном [0, 255] (clamping).

Краевые условия:

Пустой массив (size = 0) обрабатывается корректно.

Размер массива может быть очень большим (50 000 000 элементов в тестах).

Формула преобразования:


output[i]=clamp(input[i]∗1.3,0,255)

3. Базовый алгоритм (Последовательный)

Алгоритм реализован в классе DoroginVContrastRaisingSEQ.
Последовательная версия проходит все элементы массива и применяет к каждому преобразование контраста.

Пример кода:

for (size_t i = 0; i < input.size(); ++i) {
    int value = static_cast<int>(input[i] * 1.3F);
    output[i] = static_cast<uint8_t>(std::clamp(value, 0, 255));
}

Проверка корректности проводится через сравнение с эталонным массивом reference.

4. Схема распараллеливания (MPI)

Параллельная версия реализована в классе DoroginVContrastRaisingMPI.

Принцип работы:

Входной массив делится на блоки по числу процессов.
Каждый процесс обрабатывает свою часть массива.
Используются функции MPI_Scatterv и MPI_Gatherv для распределения и сбора данных.
rank 0 собирает весь массив после обработки.

Псевдокод:

scatter input -> local_block
for each element in local_block:
    scale and clamp
gather local_block -> output


Каждый процесс работает параллельно над своей частью массива, глобальная проверка не требуется, так как обработка каждого элемента независима.

Выводы по производительности:

Последовательная версия быстрее для 1–2 процессов.
С увеличением числа элементов и процессов возможен рост ускорения, но при текущем размере массива затраты на передачу данных значительны.

## 8. Заключение

Реализованы последовательная и MPI версии алгоритма повышения контраста изображения.
Функциональные тесты подтвердили корректность работы.
MPI-версия масштабируется, однако эффективность ограничена коммуникационными накладными расходами при большом числе процессов.
В целом алгоритм работает корректно и может быть использован для обработки больших изображений.

##Приложение

Пример MPI-обработки блока:

MPI_Scatterv(input.data(), counts.data(), displs.data(), MPI_UNSIGNED_CHAR,
             local_in.data(), counts[rank], MPI_UNSIGNED_CHAR, 0, MPI_COMM_WORLD);

for (size_t i = 0; i < local_in.size(); ++i) {
    int value = static_cast<int>(local_in[i] * 1.3F);
    local_out[i] = static_cast<uint8_t>(std::clamp(value, 0, 255));
}

MPI_Gatherv(local_out.data(), counts[rank], MPI_UNSIGNED_CHAR,
            output.data(), counts.data(), displs.data(), MPI_UNSIGNED_CHAR, 0, MPI_COMM_WORLD);
